The original `SensorVisibilityDef<T>.Current` and `Covers` manually captured only the sensor
component codec. A foreign entity query's outer observation captured the queried entity,
not the sensor's other components. The new independently compiled negative provider changes
the existing sibling `CompletionProbe`'s persisted counter without `Entity.Touch`.
On core2.635.0, the actual foreign entity query returned successfully: baseline22 checks
passed and two failed, including the explicit terminal diagnostic. This is a demonstrated
gap, not an inference from a search or a changed test expectation.

Both intervals now use the original `EntityObservation.ReadProvider` with the selected space
and `observeTargetState:true`. Coverage uses the actual enumerated entity; live sight infers
the actual component owner. Runtime identity and selected-space metadata are read inside
the same interval. Transient current facts retain the validated capability ID and actual
enumerated owner ID, so key construction does not reread unguarded capability/entity getters.
No new observation owner, saved field, hash algorithm, reduced codec or visibility cache.
The original exception is preserved when a provider mutates and throws; manual `finally`
verification cannot replace it with a later mutation error.
