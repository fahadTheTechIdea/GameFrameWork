## Implemented ownership

ResourceFlowJournal remains the single committed-history subscriber/owner. Its company partition now
embeds the same authored bounded FeedRing, cumulative resource/kind/cause quantity/count/timestamp
summaries and actual last-evicted tick. No parallel event, stock balance, per-metric ledger, environmental
scheduler or host calculation. Cumulative amounts use BigInteger Q32 native raw quantities; facts retain
checked signed64 sequence/ages. Retention is history policy, not a world/entity limit.

Staged whole-journal decode validates canonical unique keys, quantities/quanta, count=sole feed sequence,
timestamps/eviction bounds, retained-row dominance and exact unexpired history; failed decode preserves
original partitions. Evicted records cannot be reconstructed, so this does not prove cryptographic
integrity of every possible forged historical summary. Event fact5 stays unchanged; journal/view6
replace their prior native layouts. The current save63/build2.98 reader has no compatibility branch.

Optional sim.environment-metrics requires only sim.resource-flows. Native master-listed metrics select
explicit same-native-unit resources, physical kinds, actual nonempty Code causes, null/positive exact
window and second/minute/hour/day rate unit. Cause is the existing Code contract, not a content ID:
native `activity:...` causes remain actual identities, without rewriting or default substitution.
Cumulative amounts survive retained-feed expiry. Windows use [max(0,tick-duration),tick) and refuse
Expired when evicted facts overlap coverage; no silently truncated rate or invented zero. Rates are
reduced exact rational quantity-units per selected game-time unit, using actual session quantum.
Zero-age rates are explicitly unavailable. These are elapsed-window/lifetime averages, not guessed
instantaneous scientific emission rates or current pollution inventory.

EnvironmentalMetrics is a stateless catalog facade over IEnvironmentalMetricDefinition/Source, with
one private immutable view1 and no codec/system/subscription. Independent public proof definitions
read the same actual journal and require no scheduler edits. Pure guards cover entity versions,
owners/identities and session tick/identity allocation, not every possible cross-service mutation.
Native objective predicates author explicit metric/unit/relation/amount, resolve stable aliases then
validate exact units after all definitions resolve. Existing ObjectiveSystem owns lifecycle/pacing.
There is no automatic objective enrollment or compulsory work/map/operation module.

## Proven behaviors

- Required JSON filters/units/rate unit/window; duplicate/missing resources/kinds/causes, mixed native
  units, unknown keys, invalid/unmatched objective threshold and unaligned durations refuse explicitly.
- Pending transactions publish only via the existing event phase and prohibit lossy checkpoints.
  Actual losses count once, unrelated kinds/causes remain separate, retained facts can expire while
  cumulative metrics stay complete. No read mutates physical stock or journal state.
- Complete nonempty/empty windows and conservative incomplete-window refusal; exact reduced lifetime/
  window rates and explicit zero-age rate unavailability. Negative/future windows refuse.
- Detached immutable cumulative summaries; foreign metric/journal reads reveal no amounts, units or
  time watermarks. Foreign physical inventory remains untouched.
- Historical totals exceed long/Fix representational range through actual native resource transactions,
  serialize canonically and restore exactly. This is protocol instrumentation, not an instant player command.
- Staged negative/noncanonical/zero/impossible cumulative quantity decode rejection preserves previous
  company partitions. Malformed/mutating external metric providers fault ordinary objective execution
  and prevent a healthy checkpoint.
- A native inventory/history/metric-only session composes, updates and save-loads without spatial,
  worker, objective, operation or population providers, and creates no ghost entities.
- Ordinary incident/readiness/cancellation commands exercise actual timed machine travel, native stock
  spending, blocked cleanup, same-order resumption and restart. Spill/cleanup effects are recorded once
  only after required physical work, with exact conservation of 6 lost+3 repair+5 cleanup units.
- Objectives wait for real cleanup history and cannot complete recursively in the same Update that
  publishes it. Signed64 coverage at ages above 2^40 and exact rational rates remain valid.
- Saved blocked response, cancellation, cleanup/objective completion and evicted cumulative histories
  continue hash-identically across interleaved sessions.

## Open scope

This is physical-history environmental classification, not a scientific pollution model. Persistent
contamination layers, weather/terrain/chemical spread/severity/condition, maintenance/preparedness,
environmental pressure/cost policies, arbitrary metric sources, automation signal bridges and dynamic
incident emission rates remain open. Stock recovery is not mislabeled destruction; native cleanup here
is actual disposal. Broader checkpoint/provider/cross-service purity/fault/replay/lockstep/fuzz/stress/
allocation/full-regression and complete P12/P1–P12 acceptance remain unverified. No Oil/Tycoon/host/demo/
platform/Draw changes. Development-lifecycle guidance kept stage, code, verification and tracker aligned.
