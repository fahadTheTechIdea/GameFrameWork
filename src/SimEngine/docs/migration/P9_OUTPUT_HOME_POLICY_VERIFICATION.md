## Original owners and behavior

`ITransformationDefinition.OutputHome` projects actual immutable metadata from
the single TransformationDeclaration. Entity-output recipes must explicitly
declare `output_home: unassigned|producer|required`. Resource-only recipes have
no applicable policy. Producer/Required need spatial mobile worker metadata.
Missing/invalid/inapplicable declarations, including unused recipes, fail before
Initialize; there is no missing-key producer inference.

Original TransformerManager admission and append use
TransformationContracts.ResolveOutputHome and pass that resolved identity to
the actual named provider queue. Pure preview and actual append share the same
decision and original observation/account/queue-prefix guards. Snapshot/save
validation rejects unresolved Producer/Required entries and invalid/nonworker
bindings while permitting a retained identity whose target has since vanished.
Views expose authored policy and original resolved queue.Home, not host logic.

Native automatic finite production uses the same resolver. Required with no
explicit home reports transformation.home-required and appends no item. Explicit
commands can supply it. Repetition retains its existing selected identity;
cancellation uses the original queue and WIP disposition.

Both native and independent processors call shared CheckOutputHome BEFORE actual
result conversion/creation and shared BindOutputHome AFTER successful creation.
The latter delegates to original WorkerHomeContracts.CommitHome via its guarded
produced-worker path, rather than copying a raw IWorker.Home setter. Removal or
ownership loss cannot substitute a producer, consume held WIP or publish results.
Contract faults latch the existing session fault. Prospective connected rollout
and complete hostile-provider matrices remain separate, unfinished parent work.
