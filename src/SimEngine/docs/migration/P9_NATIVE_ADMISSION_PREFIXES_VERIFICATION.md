## Outcome

Original WorkSystem.FitsAssignmentSet previously included all ready timers and matched native jobs
across the entire queue. An infeasible low timer made the all-native set fail. Original individual
fallback could then acquire a preferred source for one machine, although selecting another actual
source would admit TWO higher-ranked machines together.

WorkSystem.MatchNativeFrontier is a private helper of that SAME owner. It finds actual full distinct
worker coverage through the unchanged matching owner, collects the FIRST uninterrupted runnable
native company activity frontier, then searches prefix lengths longest-first. Only that explicit
membership constrains fresh joint resources/docks/optional-cost feasibility; failed pure proposals
claim nothing. Existing ordered-edge matching preserves attained coverage and tries alternatives.
The selected complete prefix alone enters original fresh WorkBoard acquisition. An ordinary actual
whole-set commit refusal cannot fall through to member mutation. Runnable provider/company/standalone
boundaries are retained; blocked/unmatched/exhausted offers do not become hidden barriers.

No second scheduler, resource evaluator, reservation ledger, persisted prefix/matching state, budget,
clock, host rule or compatibility shim. Build2.299.0/save143/replay1/work-view84; layouts unchanged.
