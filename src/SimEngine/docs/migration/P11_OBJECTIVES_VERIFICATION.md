Date:2026-10-05. Current working-source evidence, not committed HEAD or full regression.
Standalone framework only; no Oil/Tycoon/platform/Draw/host gameplay implementation.

## Identity and responsibility

Build2.88.0/save58; optional objective system1/view1. Technology1/view1, Work22/work-view29 and other
native layouts unchanged. No legacy reader, implicit objective enrollment, default victory or shim.

ObjectiveModule declares existing-catalog ObjectiveDef/IObjectiveDefinition, open predicate/effect
bases and contracts. Kernel.DependencyGraph alone validates both prerequisite and condition DAGs.
Native logical all/any, actual company-owned entity-count and technology-knowledge predicates read
existing owners. Every predicate sees only declared detached child observations; no array-order logic
or implicit AND/OR wrapper. Missing/cyclic/duplicate/empty references refuse. The native outcome effect
uses the existing World.End authority, not a second victory ledger.

ObjectiveSystem aliases IObjectives and is the sole state/Sync owner. Explicit scenario enrollment
names each beneficiary and its selected objectives; required ancestors must also be explicitly enrolled.
Empty enrollment is valid; omitted settings cannot imply all content. No compulsory work, resources,
technology, spatial geometry, economy, population or combat module. A selected technology predicate
requires the actual knowledge contract; this combined physical integration is not exercised here.

Order800 executes in the existing Update loop after native work/process phases. Entire-pass condition
reads precede terminal effects; dependency activation sees pass-entry states only. Lifecycle is
Locked → Active → Completing → Completed or Failing → Failed. Terminal effect Check may wait with
typed blockers; successful Apply settles once. Failed prerequisites propagate only after committed
failure. Actual resource/job/research state is never copied.

Deadline is a positive rational duration or explicit null, converted by the current session time and
measured from activation. Tick >= deadline wins before a same-tick condition observation. Completing/
Failing retains the already-earned terminal intent while an effect waits; no reset, extension or
repeated condition evaluation. One codec owns canonical company/definition/lifecycle/timestamps/
observation/blocker/cause; prerequisite chronology and phase invariants validate on save/load/hash.
Private detached views expose progress/blockers/declared dependencies, never provider or World handles.

## Proven

- Explicit master document, actual system/service alias, unchanged work state, no compulsory technology;
  private enrollment/facts; detached readonly prerequisite lists and pure native observation hashes.
- Missing/cyclic/duplicate prerequisite or logical references, empty logic, invalid entity minimum,
  zero/missing deadline, missing effect/reference fields refuse before Initialize. Invalid company,
  duplicate/unknown enrollment and omitted prerequisites/settings refuse; explicit empty enrolls nobody.
- External public-contract stock predicate and gated effect register through an extended module without
  changes to ObjectiveSystem. Providers own no objective lifecycle/resource/work store or second loop.
- Root readiness observes20 actual supplies; all progress observes the real source without pretending
  a tower exists. Completion cannot activate another objective within the same pass.
- Ordinary player construction commands create two real point structures, hauling/consuming16 of20
  inputs over game time. Objective completion waits for the actual second structure before its effect.
- Saved Completing and Failing phases preserve activation/cause/typed wait and identical twin hashes.
  Terminal effects commit once; a saved settled objective emits no repeated external effect.
- Native final objective sets the engine outcome; engine stops Update after victory. Another company
  cannot borrow the first company's entities/stock/completion. Terminal save/hash agrees.
- Exact game-time deadline failure, next-pass failed-dependency propagation, no fake dependent activation,
  explicit null failure effects and delayed real physical failure-response conditions are verified.
- Future activation time refuses both checkpoint and hash.
