## Earlier C6b design — original settings migration

## 0. Problem

Existing IHaulLoadPolicy stores only a content profile identity. Minimum load, maximum wait, enabled
state and emergency bypass cannot be edited by the player independently of adding another JSON profile.
Extend that same capability/command/view/dispatch owner, not a fleet scheduler or per-carrier clock.

## 1. Goals

1. JSON profiles provide explicit immutable initial settings and a contract-based load decision rule.
2. One current settings record replaces the component's profile-only state. It includes selected rule,
   native per-resource minimums, exact game duration maximum wait, enabled state and emergency bypass.
3. Commands and private previews validate the same actual cargo/native capacity/resource/time rules.
4. Edits change new automatic dispatch eligibility without resetting request age/dispatch history,
   cancelling an accepted physical trip, changing stock or creating promises during preview.
5. All settings persist/hash/replay through existing component/command codecs; public providers use
   the same protocol. One game clock remains authoritative.

## 2. Design

HaulLoadSettings is detached immutable intent. IHaulLoadProfile.Initial supplies authored settings;
CheckLoad receives current settings and actual request context. IHaulLoadPolicy reads/checks/configures
one settings record. HaulLoadPolicyContracts validates and guards callbacks through the existing pure
boundary. Native and public-only capability implementations replace their profile string with settings.
Existing HaulLoadPolicySnapshot projects these settings; command/view payloads require explicit settings.

The existing component Sync embeds all fields. GameDuration gets one exact codec for its existing
rational/decimal representation; it is a duration value, never another clock. Bill lines are canonical
and checked on decode. LogisticsService retains actual request/last dispatch history and native jobs.
Definitions remain JSON content; runtime settings do not mutate shared definitions or other sessions.

## 3. API

ConfigureHaulLoadPolicyCommand.Settings replaces Profile. PreviewHaulLoadPolicy accepts the same
HaulLoadSettings. No profile-only overload/reader/default settings. A selected profile still identifies
the authored rule; runtime knobs do not replace the rule's executable contract.

## 4. Files

Standard/HaulLoadPolicies; Commands/HaulLoadPolicyCommands; Views/LogisticsView; Standard/LogisticsModule;
Core/GameTime exact duration codec; ExtensionProof/HaulLoadProof and declarations/content;
HaulLoadPolicyTests; build/save current assertions; stage/evidence/master/P9/README/help/AGENTS.

## 5. Errors

Missing settings/rule, incompatible resources/minimums/native quantum/cargo capacity and unrepresentable
maximum wait refuse explicitly. Foreign reads/edits disclose no policy. Provider mutation, missing state
or ignored commits fail through existing guarded boundaries. Corrupt settings cannot restore.

## 6. Compatibility

Breaking development contract/content state/command/view/save identity; no profile-only compatibility
command or second settings store. Old saves/builds refuse through existing identity checks.

## 7. Verification

Clean solution build, then only the two directly affected named suites:

- Haul load policies: authored contracts, deadlines and canonical admission
- Haul load policies: physical batches, dispatch history and saved continuation

Prove private/pure edit parity, immutable settings, invalid settings, native/public rule use, exact
duration codec, actual waiting/changed eligibility, non-reset age/history, loaded trip preservation,
save/load twins, session isolation and sole-clock pause. No third/family/full gate.

## 8. Risks

Minimums are per-resource alternatives, not simultaneous cargo reservations. Maximum wait is measured
from the existing request/last successful dispatch coordinate, not policy-edit time. Edits are admission
policy, not permission to erase cargo or an accepted trip.

## 9. Out of scope

Editable areas, preferred routes, fuel reserve/service cadence/trip budgets, standby input consumption,
Oil/Tycoon/hosts/demos/platforms/Draw, new clock/store/dispatcher, full regression/replay/stress/full P9.
