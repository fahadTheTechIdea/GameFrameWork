## 0. Problem

Original C3 replaced hard-coded nearest selection with authored destination policies. M108
completes a missing interaction: a held machine's retained cargo must serve an explicit private
workflow receiver, and that receiver's actual emergency classification must survive acquisition
and save/load. Extend the same selector and original job provenance; keep recovery chronology,
requests, reservations, motion and handling authoritative. Financial behavior is not involved.

## 1. Goals

1. Each authored recovery kind explicitly names a destination policy from the existing Def registry.
2. Policies evaluate detached feasible endpoint/demand facts, not mutable inventories/world/jobs.
3. Native nearest, demand-first and demand-only rules are JSON; mods can add a policy without a
   logistics/scheduler edit. Missing/invalid references fail composition before Update.
4. Recovery reserves/hauls actual residual cargo; physical demand priority and travel cost determine
   destination through the same preview/acquisition path. No repurchase/refund/generation income.
5. Demand-only waits honestly; enabled demand/change of destination resumes through engine commands.
6. Partial pickup/unload interruption and saved/retried/full physical completion conserve resources.

## 2. Design

Add immutable RecoveryDestinationFacts/Decision and IRecoveryDestinationPolicy, with Def family and
native authored definition in the existing optional LogisticsRecoveryPolicyModule. The selected
LogisticsRecoverySettings carries a required destination_policy ID, never an implicit nearest fallback.
Validate exact referenced definition at composition. No second registry, live settings or serializer.

Facts: company, source/destination/carrier IDs, resource, feasible amount, actual aggregate delivery
gap, selected actual demand priority and selected travel cost. Current request selection uses
the original emergency/priority/age/stable-identity comparator. Providers see facts only. Decision:
typed blocker or positive bounded native ceiling and nonnegative long preference. Caller verifies
participant purity and bounds/native quantum, freshly previews a reduced quantity and compares
preference, actual route cost and stable entity identity. Existing ReceivingCeiling protects maxima.
Continuing shipments still require full remaining cargo; never split an already committed reroute.

Native JSON modes: nearest_available (rank0/full feasible amount), demand_first (active demand rank
1+priority/at most gap, explicit nearest fallback for no demand), demand_only (same demand ranking,
typed no-demand refusal without fallback). Demand gaps/priorities derive from existing _demands and
DeliveryGap, not a copied demand store. Both ordinary recovery and destination replanning use the
same policy. A public-only content extension supplies a minimum-demand-priority policy.

Shared VisitPorts discovery is public-only for ordinary sources/evacuation. Recovery may receive
at a private inlet only through explicit selected active demand or an acquired original promise;
private spare room alone is excluded. HaulPreview.HaulDemand publishes the selected original
requester; existing dispatch/job.HaulDemand saves it, with no new emergency state/codec. Source
classification remains declared-contract based. Expired acquired requests lose urgency, not
their existing physical promise; Invalid refuses. A new destination adopts its own requester
when a replacement claim is committed. Fresh work never bypasses explicit hold/role/area/stock/
reserve guards. Normal nearest public recovery needs no invented requester.

WorkBoard.RetainsOrder recognizes its own exact live haul requester references before target
retention checks. Cancellation withdraws demand/work but the same original order remains the
disclosure/classification authority until the last such shipment ends. Original Prune then
drops the terminal haul and unreferenced cancelled order; no permanent history or shadow record.

Target/incident retention callbacks are pure observations, including the mutable actual order
argument. Reuse existing EntityObservation plus SyncOrder; reject target/sibling/order/clock/
space changes and preserve original throw causes. A scoped invocation guard refuses recursive
cleanup even if a provider catches its nested error. Public order enumeration denies private
orders before running their retention provider. These guards grant no work or retention policy.

Pure incident reports must also be semantically valid. The retention path reuses
IncidentPhases.ReadLifecycle for actual binding/workflow/episode/activity/history/timestamp
checks. An inactive report must match the original Done order's CompletedTick; a returned
report cannot invent a second resolution time or silently authorize pruning of earned work.

Add explicitly master-listed recovery content/profile and a nearby depot to the current physical
fixture. Player stock/hold/access commands cause actual paid partial pickup, recovery, travel, timed
unload, changed demands and completion. Test code owns no jobs/receipts/stock/account mutations.
