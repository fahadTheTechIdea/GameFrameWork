## 0. Problem

RecurringPlanBinding.ReadRequest always reads the original master template and anchor. The source
cannot select a private saved blueprint. WorkRecurringPlans.ValidateRecurringLink validates old
cycles against that definition, which would corrupt history if a future source is revised.

## 1. Goals

1. Configure future recurring template selection, anchor and group through a public source contract.
2. Resolve private IDs/revisions through the existing board, never a host or duplicate catalog.
3. Preserve exact admitted cycle ancestry despite source/library revisions or deletion.
4. Use actual physical work, typed blockers, current priority checks and the single game clock.
5. Save/hash/reload native and independent public providers with the same validation protocol.

## 2. Design

Optional IRecurringTemplateSource extends the actual IRecurringPlanSource capability. Immutable
RecurringTemplateSettings holds explicit PlanTemplateSelection, frozen provider anchor and group.
Master JSON remains the existing mandatory template/binding/group authoring; initial settings are
those explicit values, not a fabricated fallback. Non-template sources cannot accept this control.

The existing configure command family adds ConfigureRecurringTemplateCommand. Its engine preview
checks the selected private revision, whole provider structural schema/anchor, group and bounded
priority without trying to create a future site while an admitted cycle is outstanding. Selection
changes affect future cycles only. Source deletion/stale revision is a typed future request blocker;
disabled/cadence/outstanding rules retain their existing precedence. Common disable/settings control
remains available when a future source reference breaks.

WorkBoard keeps the immutable admitted PlanTemplate on the actual first plan record of each template
cycle, once. This is authored admission history, not execution, progress or another cycle ledger.
The existing plan Sync stores it. PlanOrigin identifies the actual cycle-head plan and template
kind on every member, replacing timestamp-only membership. No separate cycle counter or ledger.
Actual members/provenance/definitions/dependencies are checked
against this frozen shape, not the changing source. Every historical template cycle is checked,
including retired source entities; manual/single/trailing records cannot impersonate a template head.
Request equality also checks actual dependency links. Source callbacks cannot silently substitute
another future selection while configuring common settings or acknowledging work.

## 6. Compatibility

Direct board/component/view/save revision. No old loader, source fallback or parallel recurring system.

## 7. Verification

## 8. Risks

Never validate historical work against mutable source settings. Freeze authoring once on its actual
head and use the same canonical template codec/compiler. A broken future reference must neither
fault valid old work nor prevent disabling it. Provider settings mutation must retain normal chronology.
