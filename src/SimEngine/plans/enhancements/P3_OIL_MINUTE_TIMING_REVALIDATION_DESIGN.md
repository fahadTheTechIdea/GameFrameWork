## 0. Problem Statement

Original P3.acceptance.001 is still open: minute-based Oil sessions must retain
deterministic physical timing through explicit authored configuration. Historical
timing claims are not current-core evidence. The live Oil manifest owns six
scenario/time profiles; framework proofs already exercise actual linked Oil work,
construction and production JSON rather than copied content.

## 1. Goals

1. Prove the live manifest uniquely owns scenario/time files, all six actual
   scenario bindings resolve, and the runtime retains minute quantum/frame/rate.
2. Prove one clock, pause/speed, saved time identity and batched-vs-frame continuation.
3. Revalidate physical eight-hour pad construction/two-hour removal,108-hour
   staged drilling and sequential36-hour manufacturing on the current core.
4. Exercise the actual external Oil consumer with its focused supplied survey
   case, without modifying Oil source or running a full Oil profile.
5. Close only the exact P3 time gate if the combined evidence covers it; leave
   full-world Oil scenario, all-content, rival and profile gates separate.

## 2. Design

Embed the live Oil scenario/master JSON into the existing external proof assembly
by file link, matching existing live game-mode/work/production links. Add one
framework test that follows all six live scenario IDs into the existing explicit
OilAuthoredInfrastructureTests fixture, preserving the actual selected time/mode.
This is six profile-composition fixtures, not six full Oil worlds or a new loader.

Use existing native GameFactory/ISimulationTime/IGameClock/save/snapshot contracts.
No engine clock/state/API/default or business-rule change is planned. Existing
physical tests keep their documented role/content fixtures and physical amounts.
The public Oil survey uses full actual Oil modules with a declared small map,
one-update frame stride and six-minute work fixture; these are explicit authoring
choices, not engine size limits or canonical survey-duration claims.
