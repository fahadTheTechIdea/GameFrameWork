## Goal and boundaries

A game world may expose several named spatial data layers over a provider-owned space. A layer has a
stable identity, an opaque domain type, a deterministic storage type, units, optional vertical
reference metadata, an optional resource identity, and immutable extensible JSON metadata. Examples
include terrain classification, elevation, water surface/depth, underground deposits, temperature,
ownership, influence, fog/knowledge, and route cost. These are examples of content, not engine enums.

The engine owns contracts, registration, deterministic values, save/hash state, authorization-aware
views, and invalidation. A game/module owns what a layer means, how it is generated, and which engine
systems consume it. Hosts may inspect immutable metadata and values; they do not implement simulation
rules. Rendering remains outside SimEngine.

This is a set of data channels over a spatial provider, not an assumption that the world is a finite
three-dimensional voxel grid. A tile provider may expose stacked 2D layers with authored vertical
domains/references. A future non-tile provider may implement the same registration contract with its
own topology and storage. Spatial meaning is never inferred from names or drawing order.

## Contracts and sole ownership

- `SpatialLayerDef` is the one JSON definition for layer identity and metadata. It resolves its owning
  `SpatialSpaceDef`; its ID is unique in the existing spatial-layer definition index.
- `ISpatialLayer` is the immutable query contract: ID, owning space, opaque type code, value type,
  immutable IUnitDefinition/IResourceDefinition catalog aliases, explicit resource interpretation,
  vertical domain/unit/reference/offset, and immutable metadata.
- `ISpatialLayerProvider` registers definitions and exposes the provider-owned layer contracts. It
  is a capability of a spatial provider, not a second space or a parallel catalog.
- `SpatialLayer` is the shared resolved metadata/owner binding for live providers. MapLayer/PointLayer
  derive from it; it owns no values, registry or separate Sync. Composition validates exact selected
  registrations/catalog/vertical/frozen metadata and owner/visibility, never only a matching name.
- `TileMap` owns tile-layer values and the deterministic sparse chunk format. Current value shapes are
  byte, 32-bit integer, and engine fixed-point. Custom spatial providers may implement their own
  deterministic storage for the same contract; they must own its persistence and view projection.
- `TileMapView` exposes only viewer-authorized layer metadata and typed values. Private-layer
  visibility rules apply to metadata and values alike.
- `ISpatialLayerQuery<TRegion, TValue>` is the optional provider-owned regional query contract.
  TileMapView implements it for tile rectangles with integer and fixed-point output. This is a view
  capability, not another storage owner or a tile requirement in the kernel.
- `ISpatialLayerPagedQuery<TRegion,TValue>` is the optional bounded query contract over the same
  values. The provider defines ordering and validates geometry; SpatialLayerPaging owns generic
  offset/capacity/version admission only. Successful immutable page facts carry actual total/count/
  next offset and viewer-local version. Refusals clear output and withhold totals/versions. This is
  not a saved read transaction; retain the same layer/region and discard cursors on load/new session.

No global layer catalog is introduced. `ContentTypes` is the existing master registry and declares
the `spatial_layers` section. The owning space/provider registers its matching definitions during
composition. Composition fails if a selected provider does not register an authored layer. No layer
is silently fabricated from a missing content entry.

## JSON shape

```json
{
  "tile_spaces": [
    { "id": "world.surface", "width": 256, "height": 256 }
  ],
  "spatial_layers": [
    {
      "id": "world.elevation",
      "space": "world.surface",
      "type": "terrain.elevation",
      "value_type": "fixed",
      "visibility": "public",
      "unit": "unit.metre",
      "vertical_domain": "vertical.surface",
      "vertical_unit": "unit.metre",
      "vertical_reference": "datum.sea_level",
      "vertical_offset": 0,
      "metadata": { "generator": "terrain.default", "display_group": "physical" }
    },
    {
      "id": "world.crude_deposit",
      "space": "world.surface",
      "type": "resource.deposit_amount",
      "value_type": "fixed",
      "visibility": "public",
      "unit": "unit.barrel",
      "resource": "resource.crude_oil",
      "resource_measure": "quantity",
      "vertical_domain": "vertical.subsurface",
      "vertical_unit": "unit.metre",
      "vertical_reference": "datum.surface",
      "vertical_offset": -1200,
      "metadata": { "reservoir_model": "layered" }
    },
    {
      "id": "world.lake_level",
      "space": "world.surface",
      "type": "water.surface_level",
      "value_type": "fixed",
      "visibility": "public",
      "unit": "unit.metre",
      "resource": "resource.fresh_water",
      "resource_measure": "associated",
      "vertical_domain": "vertical.water_surface",
      "vertical_unit": "unit.metre",
      "vertical_reference": "datum.sea_level",
      "metadata": { "hydrology": "lake" }
    }
  ]
}
```

These examples require explicitly authored units/resources in master-listed JSON documents; they are
not built-in engine identities. `type`, `vertical_domain` and `vertical_reference` remain open content
identities, not closed framework enumerations. `unit`, `vertical_unit` and `resource` are references
to the existing sole catalog. Metadata is strict JSON at the definition boundary but its nested
schema belongs to the declaring game/module. Values use deterministic engine types, never floating
point. A value's unit and optional resource identity describe interpretation; they do not implicitly
convert quantities or generate deposits.

P3-S5a replaces opaque resource/unit acceptance in place. SpatialLayerDef resolves IUnitDefinition
and optional IResourceDefinition once through the existing UnitDef/ResourceDef indexes. Runtime layers
and detached snapshots alias those immutable definitions; no spatial-resource or unit registry exists.
`resource_measure` is required whenever resource is present: `quantity` validates that the value unit
and native resource unit share a dimension; `associated` permits a related property with an independent
unit (water height, coverage, temperature). No meaning is inferred from layer type/name. A measure without
a resource fails. A vertical domain requires explicit vertical_unit; offset unit is independent from
the value unit. Unknown units/resources, empty references and inconsistent dimensions fail before
Initialize with the existing authoring diagnostics. A shared layer cannot be Read/Resolved again.
This is interpretation metadata, not conversion of stored values, a deposit balance or inventory grant.
P3-S5f now enforces per-cell material legality through shared SpatialResourceValues and existing exact
unit contracts. Generation science and physical extraction still require engine-side contracts;
legal spatial availability does not mint inventory or bypass physical transactions.

`visibility` is required and is either `public` or `company_private`. A private layer without an
assigned owner is hidden from company views. Engine providers assign a session seat through
`ISpatialLayerProvider.AssignOwner`; ownership is saved and hashed. Ownership changes invalidate
affected metadata views. Observer views retain their existing full-information semantics.

Line definitions reference the authoritative layer definitions directly, and owned lines require an
explicit `owner_layer`. Network definitions reference the line by `line`, deriving both data and
ownership layers from it. The engine does not infer an owner-layer name from a suffix or construct
missing layers during module composition. A line and its owner layer must share the same space;
their value types must be byte and integer respectively.

## Runtime rules

1. Definitions are immutable after content resolution; layer values are mutable world state owned by
   their spatial provider.
2. Missing space, duplicate layer ID, unknown storage type, invalid provider registration, out-of-space
   coordinates, or malformed metadata fails explicitly.
3. Sparse defaults are zero. A provider may choose a different storage representation but must state
   it in the registered layer contract and serialize/hash values deterministically.
4. Layer writes update provider invalidation versions. Snapshot metadata and values are detached or
   immutable and obey the same visibility policy.
   Regional reads return `Success`, `Unavailable`, `ValueTypeMismatch`, `InvalidRegion`, or
   `BufferCapacityExceeded`. Missing and hidden identities deliberately share `Unavailable`. Refusal
   clears the caller's output and returns no fabricated zero readings. Zero is only a valid default
   for an unallocated cell inside an authorized layer. Requests beyond a single IList's count
   representation require smaller regions; that bound is not a world-dimension limit.
5. Resource quantities do not bypass inventories or transactions. A deposit layer describes spatial
   availability; extraction remains an engine-owned physical workflow that transfers value into the
   authoritative resource/inventory system.
6. Sea/lake level, subsurface depth, altitude, or any other vertical convention is explicit metadata.
   The engine does not assume a fixed axis, datum, world size, renderer projection, or camera.
7. Adding a new semantic layer requires JSON and a provider/generator/consumer contract. Adding a new
   storage representation requires an explicit provider/content registration contract, never edits to
   unrelated simulation schedulers.

## Current implementation slice

- `spatial_layers` is registered in the engine's master content schema.
- `SpatialLayerDef` resolves space, stable semantic/resource codes, typed storage, units, vertical
  metadata, and immutable extension JSON.
- `ISpatialLayer` and `ISpatialLayerProvider` define the provider boundary; TileMap registers authored
  definitions during composition.
- TileMap now has sparse fixed-point layers in addition to sparse byte/integer layers; fixed values
  participate in save/hash state and use the selected immutable view API.
- Standard line and network definitions resolve authored layer/line references and validate value
  types and space identity. Bare layer-creation APIs and inferred owner-layer suffixes are removed.
- Private ownership participates in the map's schema 4 save/hash state. Private data changes do not
  change another company's invalidation cursor; unassigned private layers remain hidden to companies.
- Layer metadata views return detached `SpatialLayerSnapshot` values rather than storage providers.
- A shared chunk-coordinate codec now writes coordinates during both save and hash traversal; the
  earlier sparse-layer source had only read them. This correction is source-reviewed and build-checked.
- World composition no longer rejects unrelated space-bound entity definitions. Spawn checks the
  selected provider against the entity's declared space.
- Provider-owned regional queries use one visibility/region validator and exact storage types.
  `CopyLayer`/`CopyFixedLayer` zero-substitution paths are removed, not preserved as aliases.
- Standard, projection, state, and content proof fixtures compile against authored spaces/layers and
  current provider contracts. Nonspatial lifecycle fixtures no longer invent a map to spawn entities.
- Two exact spatial-layer suites now cover authored semantic channels/catalog validation, typed refusal,
  private ownership, detached metadata, sparse coordinates, save/hash and continuation: 68 checks,
  zero failures/aborts. The former malformed-definition suite is consolidated into the directly
  affected catalog/query suite. No broader suite/filter was run.
- The entire solution builds with zero warnings/errors. See
  [scoped current and historical evidence](../../docs/migration/P3_SPATIAL_LAYERS_VERIFICATION.md).
- P3-S5b extends the existing non-tile PointSpace through public contracts with a master-listed
  point-layers.json, provider-owned fractional-coordinate regions, sparse exact samples, commands,
  private immutable views and one embedded codec. No TileMap/NavService/scheduler point special case.
  Saved twins/session isolation, provider admission before Initialize and corrupt saved sample refusal
  pass with the existing saved tile suite: 132 / 2. See [provider evidence](../../docs/migration/P3_LAYER_PROVIDER_VERIFICATION.md).
