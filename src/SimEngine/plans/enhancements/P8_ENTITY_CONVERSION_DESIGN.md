## Problem and outcomes

Transformations.cs Deliver currently spawns entity_output before CommitConversion. A failed resource
provider can therefore create an unearned result entity. The resource operation also publishes success
before any later entity initialization failure. Integrate an explicitly prepared entity result into
the same transaction, with ordinary whole-admission refusal and deferred success publication.

1. Engine-owned IEntityCreation is an ephemeral, current-session/current-tick intent, not a live entity
   or reservation ledger. Preparation validates actual catalog/company/source/geometry/identity range
   without allocation, creation, OnCreate, initialization, claims, RNG or saved state.
2. Existing World/EntityStore remain the only creation owners. Revalidate the intent before real Spawn;
   actual component/spatial/initialization hooks remain on that same path. No ghost store or rollback.
3. EvaluateConversion/CommitConversion require an explicit IEntityCreation argument (null means only
   resources). All-empty resources are lawful only with an actual entity result. Company must agree.
   Returned ResourceInventoryResult carries the actual CreatedEntity and typed entity blocker.
4. Actual resource deltas complete before entity creation. Entity initialization and subsequent shared
   endpoint verification complete before conversion facts publish. Failed resources never spawn the
   result; failed initialization faults the session and cannot publish resource success/checkpoint.
5. Native material/entity, entity-only, blocked placement/output, repeat, home assignment and saved
   continuation use the same protocol. No special instant or old entity-result completion path.

## Contract and single-owner changes

Kernel/EntityCreation.cs contains IEntityCreation and its engine-created immutable implementation plus
another partial file of World. It carries selected EntityDef, company, explicit optional producer,
placement, prospective entity ID and current tick; internal session identity cannot be forged by a
caller. World.PrepareCreation/CheckCreation/CommitCreation guard that same intent. EntityStore exposes
its existing next identity internally; it remains sole allocator. Preparation does not instantiate a
component, consume an ID or persist an intent. Stale/foreign/reused intents refuse; no inferred source,
location or different prototype is substituted. Pure placement callbacks guard actual producer version
and entity sequence. EntityRollout pure checks guard those facts too.

ResourceTransactions checks that result prototypes have empty authored opening inventory: conversion resource outputs are explicit,
not unaccounted starter-stock grants inside the result. This validation applies to prepared conversion
results, not ordinary scenario creation. Existing transformation composition checks it before Initialize.
Module-defined components and selected spatial providers remain extensible through normal contracts.

ResourceConversions.cs extends the sole owner: complete structural/native endpoint capture precedes
entity admission, which must preserve captured participants even on refusal. Recheck before actual
entity creation; changes during committed provider execution are faults, not late ordinary refusal.
After initialization, verify every participating stock/book/metadata/version again, then publish the
existing deferred flow facts. No new event, process store, codec, entity queue or callback transaction.
CreatedEntity references the actual registered result only; material-only calls explicitly pass null.

Transformations.cs removes eager Spawn and separate material-free bypass. Native completion builds
one resource intent and optional engine-prepared entity intent. Typed refusal retains real WIP/tools/
progress. Successful conversion returns the actual entity for existing home/event/notification handling.
View preview uses the same preparation admission but never retains a commit handle. Existing public
conversion proof commands save stable prototype request data, reconstructing a fresh intent each pass;
never serialize an ephemeral session handle.
