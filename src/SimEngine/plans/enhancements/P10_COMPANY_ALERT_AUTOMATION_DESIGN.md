## 2. Design/API

ControlTargetKind { Entity, Company }; ControlBinding exposes Kind and explicit ForCompany(capability),
entity constructor remains explicit entity intent. Binding codec persists kind; no inferred legacy None.
IControlActionPolicy declares TargetKind, CopyTargetIds receives actual company plus entity/None.
IEntityControlCommand remains entity command contract; independent ICompanyControlCommand exposes
actual TargetCompany. Shared dispatch selects by declared kind, stamps existing beneficiary only,
copies ordinary codec, checks actual payload/header/target before and after handler Check.

AutomationSettings accepts typed target, rejects company signal input. AutomationSystem's structural
reference admission delegates target kind/ownership through SAME shared dispatcher; no alert-specific
branch in scheduler. Existing rule target conflict identity includes kind/capability/entity. Pending
decision still applies next simulation Update, not a second inbox/scheduler/clock.

CompanyAlertControlActionPolicyDef JSON declares command/owner, enabled and disabled explicit
CompanyAlertSettings. Boolean enabled/disabled action with target0/unit.boolean selects settings;
no implicit profile/reserves/level defaults, invented scalar level or money. ContentDependencies
publish actual profiles so existing hidden-content gate also withholds dependent rule metadata.
Readiness/actual mutation still normal ConfigureCompanyAlertCommand handler and ICompanyAlertPolicy.

OperationsView discovers private company targets through explicit company API; profile snapshots
publish target kind. Company command can't be redirected to another seat. Exact observer explicit.
Pure guards scoped clock/entity facts; no arbitrary provider/service-mutation sandbox claim.

Implemented private alert/rule view guards also reject malformed negative/nonseat identities instead
of treating every negative viewer as observer. No company codec/store added: only automation binding
kind changes its existing codec, view identities change for typed target metadata/admission.

Current cached CompanyAlertView reads additionally perform original World.RequireHealthyUpdate
through Access; CopyAlerts clears its list and preflights before its invalid/empty shortcuts.
TryRead outputs clear before Access. Preserve original fault, public refusal semantics while healthy,
and actual native alert payload. Provider failures do not become healthy hash/view results.
Current player settings read immutable AutomationProfileSnapshot; the repeated variant explicitly
authors response automatic_supply. Normal dispatcher/ports/work/clock own all behavior; later
acquired emergency jobs are not fictitious queued offers.
