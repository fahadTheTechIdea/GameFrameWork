## Goal and ownership

One catalog authority: ResolvedContent implements `IResourceCatalog` in P7-A.
One live balance owner per inventory/buffer: the existing IInventory provider.
One reservation record per commitment: C1 replaces endpoint anonymous state with embedded owned records;
existing jobs retain token references, not copied quantities or a separate held-flag authority.
A transaction coordinator owns validation/commit orchestration, not a second inventory or reservation
balance. Tokens live with their owning endpoint/job; indexes contain references, not copied quantities.

ResourceId/ResourceAmount and contract-authored definitions are the current model. ResourceDef and
BasicResourceDef are native implementation choices, not mod inheritance requirements. ContentTypes
registers native or independent definitions against the same catalog contracts. No old item alias,

## Atomicity and physical flow

1. Evaluate a complete intention against source availability, destination compatibility/capacity,
   existing promises, provider versions and owner authorization; preview changes nothing.
2. Acquire a single ordered commitment containing source stock, destination capacity and, when
   applicable, the selected carrier/tool/dock references. Acquire all or none.
3. Consume/release only using its owner token. Reject double release/foreign consumption; never
   clamp an invalid release to conceal lost accounting.
4. Physical delivery remains WorkSystem/LogisticsService work. Reservation is not movement.
5. Validate every participant before commit; built-in providers must offer a no-throw commit after
   validation. An extension violating that protocol faults the session; do not fabricate compensation.
6. Transfer source balance to actual cargo/WIP/destination ownership once. A resource-flow journal
   records events/diagnostics, not a second stock total. Authored creation/destruction/conversion is
   explicit and accounted; network removal must not silently erase contents.
7. On cancellation/despawn, release unspent promises and use authored physical return/spill/scrap
   policy for owned cargo. Spent inputs are not automatically recreated.

fixture exercising split/merge/selection/save semantics. Do not bolt another lot ledger beside Storage.
