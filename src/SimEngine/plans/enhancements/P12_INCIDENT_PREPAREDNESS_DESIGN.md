## 0. Problem

Company reserves describe simultaneous role capacity, not whether a machine can serve a particular
incident. IIncidentResponse.ResponsePlan currently disappears while inactive, preventing pre-incident
inspection of the authored response DAG. Hosts must not infer requirements, access or preparedness.
IncidentsView has current episodes/phases and WorkView has per-node candidates, but no prospective
target response view or distinct current-frontier capacity. Do not invent an incident to query it.

## 1. Goals

1. IIncidentResponse always exposes its actual authored response definition; active episode is separate.
2. Existing work/incident contracts compute prospective and active target readiness, never host logic.
3. Machine candidates use one existing selector and its role/eligibility/area/route/dock/requirement checks.
4. The existing response DAG alone determines dependency/frontier/progress; parallel machine nodes
   need distinct actors, while sequential stages may reuse them after physical completion.
5. Private detached facts expose current criteria, candidate blockers, frontier coverage and shortage.
6. Reads create no incident/order/job/material claim/time. Actual dispatch always rechecks live facts.

## 2. Design

IIncidentResponse.ResponsePlan is always authored, never null merely because inactive. Native and
public providers replace conditional getters. No new definition/runtime duplicate or inactive fallback.

WorkSystem adds CopyResponseCandidates on IWorkerDispatch and delegates to its existing selector's
single private core. It resolves actual target/source/plan/node and existing response order itself.
Only this authenticated pure context previews emergency-eligible machines before an incident; it
does not post/preempt/acquire. Active queries retain actual incumbent/episode/job bindings.
Shared CheckWorker now refuses zero effective work rate as well as execution blockers. The focused
readiness proof exposed this pre-existing admission gap; fixing the shared owner also prevents normal
zero-rate assignment and material consumption, rather than merely hiding such actors in a new view.

WorkBoard implements IIncidentPreparedness as an alias of the existing board. ReadPreparedness uses
that source's declared DAG, native node records and shared requirement/worker evaluator. No temporary
Order/ActivityNodeExecution/incident, second plan graph, scheduler or reservation state. Future nodes
show current criteria but are not current frontier; dependency completion uses existing DAG state.

Extract D12's iterative maximum matching into one internal stateless DistinctWorkerMatching algorithm
used both by company reserve capacity and response frontier capacity. Callers supply actual eligible
worker identities; one actor covers at most one current parallel machine node. Assigned incumbents
are fixed to their actual node in the readiness projection. Canonical graph/worker identities govern
matching. Diagnostic assignments do not acquire a worker, tool, money, dock or material.

IncidentPreparednessSnapshot/Node are copied immutable values with target/source/plan/episode/current
order/state/game-clock observation, dependency IDs, criteria/candidates, frontier and coverage. Readiness
means ReadyForFrontier NOW, not future workflow success, guaranteed arrival, simultaneous material or
dock allocation, emergency supply feasibility, or scientific certification. Physical execution remains
the same existing jobs. IncidentsView owns viewer privacy; no executable definitions escape to hosts.

IWorkerDispatch.CopyResponseCandidates(world, target, source, nodeId, destination).
