## 0. Problem

LogisticsReferenceReplacement checks port compatibility but not authored evacuation disposition. A destination that is private or not evacuating may pass preview and then fault commit. Existing recovery origin/endpoint rebinding also lacks focused physical chronology proof.

## 1. Goals

Refuse incompatible recovery-source upgrades before work, retain compatible evacuation/cargo-return origin age and endpoint binding, and prove physical dispatch after replacement through existing owners.

## 2. Design

Move Public/Evacuate metadata into IInventoryDefinition, where all stock metadata can declare physical disposition. IStorageDefinition inherits it instead of redeclaring it. Migrate actual implementations in place; the independently authored single-resource provider reads these flags from JSON and uses them at runtime.

The existing logistics reference owner checks evacuation disposition and retained named-port key/runtime/codec, and requires a retained transporter binding for cargo-return intent. Original recovery records retain Created and LastDispatch; actual commit binding verification remains authoritative. No second recovery table, inventory owner or scheduler.

## 3. API/state

Required inventory disposition metadata and a typed replacement recovery-source refusal. Build2.566.0/save157/replay1; existing codecs unchanged.

## 4. Files

Capabilities and existing logistics replacement owner; actual independent inventory definitions; explicit recovery-replacement JSON; focused public-player proof; current protocol and tracker.

## 5. Errors

Private/non-evacuating destination, missing/changed named binding or lost transporter refuses before mutation. Actual runtime binding mismatch still faults the original replacement boundary rather than inventing stock or resetting intent.

## 6. Compatibility

Mandatory metadata migration; no fallback, legacy wrapper or duplicated disposition declaration.

## 7. Verification

Native/direct evacuation with default buffers and named aliases, plus native cargo return: held fleet, staffed upgrade, old age/endpoint rebinding, saved twins, physical recovery, conservation and refusal parity. Alias discovery retains the actual canonical default binding; acquired/live named endpoint breadth is not inferred. Focused tests only.

## 8. Risks

ER9b covers one carrier with an independent entity-owned cargo inventory in both
replacement directions. ER9c adds selected two-carrier shared-buffer arbitration
and cancellation/handoff. Larger fleets, combined shared replacement workflows
and arbitrary live named/non-entity endpoint mappings remain broader migrations. A retained
codec does not establish arbitrary custom selector semantics; provider admission
and actual commit binding checks remain strict. The point proof provider requires
explicitly authored reach1 for adjacent mobile servicing; movement/collision
remains its sole responsibility, not driver gameplay.
