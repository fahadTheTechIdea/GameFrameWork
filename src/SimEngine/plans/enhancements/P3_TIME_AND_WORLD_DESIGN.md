## Outcome

The framework runs a deterministic simulation with or without space, with a game-authored time scale.
OilFieldDays will select its minute-based calendar explicitly during P5; no current oil gate is claimed.
No map/entity limit is inherited from a rendering platform.

## Time design

Replace static oil-minute assumptions with one immutable time definition per session, resolved from
the game manifest/scenario before initialization. It specifies simulation quantum, default update/frame
step, and optional calendar/horizon. Author exact integer/rational units; do not round through floats.
The clock owns elapsed host-time accumulation; authoritative game time is an integer tick index.

Separate simulation tick, elapsed game duration, calendar projection, and presentation interpolation.
Hourly/daily schedules request configured game durations/calendar providers rather than global constants.
Games with no calendar need no fabricated dates. A horizon is an explicit game rule, not mandatory.
Use checked arithmetic and a sufficiently wide tick/duration representation consistently in commands,
systems, state-age fields, saves, hashing, lockstep and views; eliminate old int-minute conversion paths.

Review `GameClock`, `GameTime`, `GameDate`, `TickInfo`, schedules, scenario frame/horizon fields, and every
caller. Replace old fields instead of accepting both `frame_minutes` and a new competing time definition.
Catch-up budgets bound work per host update, not supported game duration or map size. Document how
retained backlog and interpolation behave while paused, ended, or faulted; interpolation must stay within
its declared bounds. Reject invalid/overflowing configuration with typed diagnostics.

## World and spatial design

Keep the world as entity/service/system authority. Stop requiring `TileMap`, width/height defaults, or
spatial placement to initialize a session. Register spatial services explicitly when content requires them.
Tile navigation remains a reusable provider; do not implement a 3D renderer/physics engine for extraction.

Entity identity, state, ownership, and Update do not imply tile position or vehicle kind. Spatial presence
is an optional capability with provider-owned coordinates, occupancy, routes, and distance. Placement
and travel consumers require a compatible provider; missing space refuses the content using it rather
than silently generating a map. Remove mandatory vehicle-only previous-position capture.

Snapshots expose identity/state plus registered optional presentation facets. A nonspatial game can
publish a valid simulation snapshot without map dimensions. Spatial queries/deltas belong to their providers and use
immutable projections with deterministic ordering. Clients never reproduce occupancy or route rules.

## Lifecycle preservation

- Initialize composes/validates once and settles the initial entity state through existing lifecycle rules.
- Game.Update advances through the single clock/kernel path. Each live entity is updated exactly once
  per executed tick; capability state changes settle through its entity-owned resolver.
- Cross-entity systems coordinate deterministic shared work before the declared entity-update phase.
  They do not replace it with a host-side update or independently write entity state.
- Define births/removals during a tick explicitly so a created entity is not updated twice and removed
  entities are not invoked. Persist the resulting state and birth/state-age ticks.
- Initialize and Update publish simulation snapshots. Drawing is a later game-platform responsibility,
  not an engine phase. No Draw/Drawn API or render model is implemented here.
- Diagnostic tick batches remain delegations to Update, not a second game loop.

## Scale and limits

Game-authored world extents are allowed; platform-imposed global caps are not. Detect actual allocation,
coordinate overflow, invalid capacity and protocol size errors explicitly. Performance budgets, bounded
queues and transport packet limits are named settings with clear units and purpose, not hidden world limits.
Do not promise infinite memory or remove safety checks to satisfy openness.
