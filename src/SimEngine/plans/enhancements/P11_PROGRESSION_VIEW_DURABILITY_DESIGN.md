# P11-A4 — progression view durability

Scope: existing TechnologyService, ObjectiveSystem and their thin public views. No new progression, knowledge, fault, scheduler or clock owner. No Tycoon, Oil or platform changes.

## Original defects

Technology and objective queries can return missing/unseated results before the original World health guard. Both collection queries clear caller-owned retained facts before complete observation. Objective predicate query exceptions escape without necessarily latching the original session fault. Objective menus and direct observations do not apply original content visibility.

## Implementation

1. Require the original World to be healthy before all selected early-return paths.
2. Observe actual selected technology/objective metadata and objective predicates using EntityObservation.ReadProvider; preserve the first thrown callback error, including invalid returned observations.
3. Build detached collection results locally. Publish only after all observations succeed and the original World remains healthy. This is engine observation atomicity, not transactional guarantees for an arbitrary caller-supplied IList implementation.
4. Apply existing content visibility to objective entry menus and direct objective observation. Hidden entries return NotFound without running their predicate. Do not invent a second visibility owner.
5. Leave authored dependency semantics, enrolled lifecycle, earned work, CompanyKnowledge, saves and the single clock unchanged. Transitive hidden prerequisite metadata, arbitrary private CLR purity and broad P11 privacy acceptance remain open.
