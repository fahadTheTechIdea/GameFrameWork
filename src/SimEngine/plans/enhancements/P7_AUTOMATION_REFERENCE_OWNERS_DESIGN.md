## 0. Problem

AutomationSystem.Settings owns live input/target identities. Configure resets candidates and pending decisions; replacement cannot use it as a repair. Named stock action capabilities also encode endpoint identities.

## 1. Goals

Rebind through the existing replacement owner protocol, preserve every existing rule state/timing field, and let the existing action-policy contract interpret its own typed target. Prove physical upgrades, pending decisions, saved twins and typed refusal through public commands/views.

## 2. Design

AutomationSystem implements IEntityReplacementReferenceOwner. Signal inputs use actual destination signal metadata/schema and retained component identity/codec. IControlActionPolicy declares mandatory CheckReplacement and RebindTarget methods; no generic capability-string rewriting.

Native operation, outlet reserve, stock and company policies implement their own semantics. Stock uses the existing typed binding parser/formatter and ILogisticsStockPolicies.CheckStockTargetReplacement/RebindStockTarget. The sole LogisticsService implementation owns prediction and actual physical access, sharing original policy/selection/topology and stock-source claim checks. Local endpoints remap to the replacement entity; retained independent originals remain exact; fresh bindings use explicit initial metadata. The common resource-action base retains native unit/nonnegative checks, not a second port resolver.

Commit prepares typed replacement settings, validates actual signal providers and the policy's target identity before publication, and updates only Record.Settings. Stock target rewriting never reads/recreates demand rows and does not require the logistics callback to have run first. It validates actual prepared registered access through the existing PhysicalPort path. Replacement never calls Configure, evaluates a rule, creates a command, resets a latch or advances a timer. Existing Update still applies pending control next step through the normal stock command.

Internal observation Sync recognizes valid same-update candidate/application timestamps and a decision due next update. Ordinary writers, hashes and loads retain strict between-update validation; no persisted field or alternate clock is introduced.

## 3. API/state

Mandatory action-policy replacement methods take actual World/company/target/source and destination metadata or entity. Existing ILogisticsStockPolicies gains required pure CheckStockTargetReplacement(source,destination definition,resource,port,original,quantity) and RebindStockTarget(source,prepared entity,resource,port,original,out endpoint). One implementation, no default or compatibility path. Existing AutomationSettings remains the complete binding and system codec5 is unchanged. ## 5. Errors
